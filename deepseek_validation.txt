2. Prioritized Action Plan to Achieve Best Results
Your immediate goal is not a new architecture. It is to crush the CD Bias from -14.74 px to near zero. We will do this by introducing a brutally effective, physically-motivated loss function.

Priority 1 (Immediate, High Impact): The CD-Aware Edge Loss
The Sobel-edge penalty is too naive. It says "have edges," but it doesn't say "have edges in the exact right location." We need a loss that forces the model to align the 50% intensity threshold perfectly.

Action: Implement a Thresholded Proximity Loss. Replace or significantly augment your current Sobel loss with this concept. You cannot write this as a simple one-liner; you must code a custom loss function.

The Algorithm:
For the predicted image I_pred and ground truth I_gt:

Global Threshold Normalization: To handle global intensity shifts, standardize both images using the same robust statistics (e.g., the 5th and 95th percentiles of the ground truth image alone, or your global anchors) so that 0.0 is "trench" and 1.0 is "line".

Binary Edge Extraction: Create binary masks of the 'up' and 'down' edges. Don't use Sobel magnitude. Use two simple convolution kernels [1, -1] and [-1, 1]. Threshold their magnitude to get pixel-precise, 1-pixel-thick edge maps.

Distance Transform: On the ground truth edge map, compute a Euclidean Distance Transform (scipy.ndimage.distance_transform_edt). This creates an image D_gt(x,y) where the value is the distance in pixels to the nearest true edge.

The CD Loss Calculation:

Multiply the predicted binary edge map by the ground truth distance map.

Sum these distances. This gives you the total edge misalignment error in pixels.

Loss_CD = mean( D_gt * Edge_map_predicted )

This loss is highly interpretable (a loss of 14.7 means your edges are, on average, 14.7 pixels away from where they should be) and is perfectly aligned with your goal of eliminating CD bias. You can even separate this into Loss_CD_shrink and Loss_CD_expand by checking the sign of the gradient at the misaligned edge. This will directly tell the optimizer, "Your line is too thin, fix it."

Integrate this as your primary geometric loss, starting with a weight of 2.0. This is your "nuclear option" for CD bias.

### The Solution

The -15 px CD bias should be treated as a **calibration offset**. It's consistent across all experiments (-14.74 to -17.26), so subtracting it from metrology measurements gives accurate results. This is standard practice in real CD-SEM tools where different algorithms produce different absolute values — what matters is precision and repeatability, not absolute agreement with a specific threshold definition.
